# Campus Portal API (backend)

Express + JWT API. One database driver, `@libsql/client`, for both environments:

| Environment | Database | Selected by |
|---|---|---|
| Your laptop | SQLite file at `DB_PATH` (default `backend/data/campus.db`) | `TURSO_DATABASE_URL` empty |
| Render (production) | Turso (hosted libSQL, region closest to Singapore) | `TURSO_DATABASE_URL` + `TURSO_AUTH_TOKEN` set |

Render's free tier wipes the local disk on every restart, which is why production data lives in Turso.

## Run locally

```bash
cd backend
cp .env.example .env        # then set JWT_SECRET (command is in the file)
npm install
npm run db:seed             # only seeds an empty database
npm run dev                 # http://127.0.0.1:3000/api/health
npm test
```

Seed accounts: `admin` / `admin123`, `andi` / `student123`, `bella` / `student123`.

## Environment variables

| Name | Laptop | Render |
|---|---|---|
| `JWT_SECRET` | random, 32+ characters | generated by Render |
| `DB_PATH` | `./data/campus.db` | not used |
| `TURSO_DATABASE_URL` | **empty** | `libsql://…turso.io` |
| `TURSO_AUTH_TOKEN` | **empty** | read & write token |
| `CORS_ORIGIN` | `http://localhost:5173` | comma-separated list of the deployed web origins |
| `HOST` / `PORT` | `127.0.0.1` / `3000` | set by Render (`0.0.0.0`, `$PORT`) |

## Production

- Deployed from `render.yaml` (root directory `backend`, `npm ci`, `npm start`, health check `/api/health`).
- Production is seeded **once**: `TURSO_DATABASE_URL=… TURSO_AUTH_TOKEN=… npm run db:seed`, passed on the
  command line so the values never sit in a laptop `.env`. Running it again changes nothing: the seed
  refuses to touch a database that already has rows.
- The free instance sleeps after about 15 minutes idle; the first request afterwards can take up to a minute.

## Deployment checks owned by the backend

1. `https://<service>.onrender.com/api/health` returns `{"status":"ok","database":"ok"}`.
2. `GET /api/courses` with a token returns the 6 seeded courses.
5. Create a record, restart the service on Render, and the record is still there (data is in Turso).

## Rules the code keeps

- Every list route filters by `req.user.id`, which comes from the verified token. A user id sent in the
  query string, a header or the body is ignored (see `list routes scope by the token…` in the tests).
- Roles are read from the database on every request, not from the token.
- Secrets live only in `.env` (ignored by git) and the Render dashboard.
